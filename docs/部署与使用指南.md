## 项目简介

**Oh My OpenCode** 是一个功能强大的 OpenCode 插件，提供多模型智能体编排、并行后台任务执行、LSP/AST 工具集成等企业级功能。

### 核心特性

- 🤖 **多智能体协作**：Sisyphus (主智能体)、Oracle (架构调试)、Librarian (文档搜索)、Explore (代码探索)
- ⚡ **并行任务执行**：像真实开发团队一样同时运行多个智能体
- 🔧 **完整工具链**：LSP 支持、AST-Grep、会话管理
- 🎯 **Claude Code 兼容**：完整的钩子系统、命令、技能支持
- 📚 **内置 MCP**：网络搜索 (Exa)、官方文档 (Context7)、GitHub 搜索 (Grep.app)

## 系统要求

### 必需

- **OpenCode**: >= 1.0.150 版本
- **操作系统**: macOS (ARM64/x64)、Linux (x64/ARM64/Alpine)、Windows (x64)
- **包管理器**: Bun 或 npm/npx（Bun 推荐）

### 订阅要求（至少选择一个）

选择以下至少一个订阅服务：

1. **Claude Pro/Max** (强烈推荐 - Sisyphus 智能体最佳体验)
2. **OpenAI/ChatGPT Plus** (Oracle 智能体使用 GPT-5.2)
3. **Google AI** (Gemini 3 Pro - 前端 UI/UX 智能体)
4. **GitHub Copilot** (备用方案)
5. **OpenCode Zen** (opencode/ 模型访问)
6. **Z.ai Coding Plan** (GLM-4.7 模型 - Librarian 智能体)

**⚠️ 重要提示**: Sisyphus 智能体强烈推荐使用 Opus 4.5 模型。使用其他模型可能导致体验显著下降。

## 快速开始

### 最快速的安装方式（推荐）

将以下内容复制粘贴到你的 LLM 智能体（Claude Code、AmpCode、Cursor 等）：

```
安装并配置 oh-my-opencode，请按照以下说明操作：
https://raw.githubusercontent.com/code-yeongyu/oh-my-opencode/refs/heads/master/docs/guide/installation.md
```

让 AI 智能体帮你完成安装 - **人类会犯错，智能体不会**。

### 手动安装（不推荐）

如果你坚持手动安装：

```bash
# 运行交互式安装器
bunx oh-my-opencode install
# 或使用 npm
npx oh-my-opencode install
```

按照提示配置你的订阅和认证信息。

## 详细部署步骤

### 步骤 1: 检查 OpenCode 安装

```bash
# 检查 OpenCode 是否已安装
opencode --version

# 应该显示 1.0.150 或更高版本
```

如果未安装，请访问 [OpenCode 官方文档](https://opencode.ai/docs) 进行安装。

### 步骤 2: 确定你的订阅配置

根据你拥有的订阅选择相应的安装选项：

| 订阅服务 | 安装标志 | 使用模型 |
|---------|---------|---------|
| Claude Pro/Max | `--claude=yes` 或 `--claude=max20` | Opus 4.5 (Sisyphus) |
| OpenAI/ChatGPT Plus | `--openai=yes` | GPT-5.2 (Oracle) |
| Google AI | `--gemini=yes` | Gemini 3 Pro (前端智能体) |
| GitHub Copilot | `--copilot=yes` | 多模型代理访问 |
| OpenCode Zen | `--opencode-zen=yes` | opencode/ 模型 |
| Z.ai Coding Plan | `--zai-coding-plan=yes` | GLM-4.7 (Librarian) |

### 步骤 3: 运行安装器

根据你的订阅情况运行相应的命令：

#### 示例 1: 拥有所有原生订阅
```bash
bunx oh-my-opencode install --no-tui \
  --claude=max20 \
  --openai=yes \
  --gemini=yes \
  --copilot=no
```

#### 示例 2: 仅有 Claude 订阅
```bash
bunx oh-my-opencode install --no-tui \
  --claude=yes \
  --gemini=no \
  --copilot=no
```

#### 示例 3: 仅有 GitHub Copilot
```bash
bunx oh-my-opencode install --no-tui \
  --claude=no \
  --gemini=no \
  --copilot=yes
```

#### 示例 4: 使用 OpenCode Zen
```bash
bunx oh-my-opencode install --no-tui \
  --claude=no \
  --gemini=no \
  --copilot=no \
  --opencode-zen=yes
```

安装器会自动：
- 在 `opencode.json` 中注册插件
- 根据订阅标志配置智能体模型
- 显示所需的认证步骤

### 步骤 4: 配置认证

根据你的订阅完成以下认证步骤：

#### 4.1 Anthropic (Claude) 认证

```bash
opencode auth login
# 选择 Provider: Anthropic
# 选择 Login method: Claude Pro/Max
# 在浏览器中完成 OAuth 流程
```

#### 4.2 Google Gemini 认证

首先，添加 opencode-antigravity-auth 插件到配置：

编辑 `~/.config/opencode/opencode.json`:
```json
{
  "plugin": [
    "oh-my-opencode",
    "opencode-antigravity-auth@1.2.8"
  ]
}
```

然后进行认证：
```bash
opencode auth login
# 选择 Provider: Google
# 选择 Login method: OAuth with Google (Antigravity)
# 在浏览器中完成登录
```

**多账户负载均衡**: 该插件支持最多 10 个 Google 账户。当一个账户达到速率限制时，会自动切换到下一个可用账户。

#### 4.3 GitHub Copilot 认证

```bash
opencode auth login
# 选择 Provider: GitHub
# 通过 OAuth 进行身份验证
```

### 步骤 5: 验证安装

```bash
# 检查 OpenCode 版本
opencode --version

# 验证插件已加载
cat ~/.config/opencode/opencode.json | grep oh-my-opencode
# 应该在 plugin 数组中看到 "oh-my-opencode"

# 使用健康检查工具（可选）
bunx oh-my-opencode doctor
```

## 使用指南

### 基础使用

Oh My OpenCode 提供两种主要工作模式：

### 模式 1: Ultrawork 模式（快速工作）

**适用场景**: 快速开发、日常任务、简单功能实现

只需在提示中包含 **`ultrawork`** 或 **`ulw`** 关键词：

```
ulw 为我的 Next.js 应用添加身份认证功能
```

智能体会自动：
1. 探索代码库理解现有模式
2. 通过专业智能体研究最佳实践
3. 按照你的约定实现功能
4. 通过诊断和测试进行验证
5. 持续工作直到完成

**示例提示**:
```
ulw 修复所有 ESLint 警告
ulw 实现用户注册和登录功能
ulw 优化数据库查询性能
ulw 编写单元测试覆盖 auth 模块
```

### 模式 2: Prometheus 模式（精确工作）

**适用场景**: 复杂任务、多天项目、关键生产变更、需要详细规划的工作

按 **Tab** 键切换到 Prometheus (规划器) 模式。

**工作流程**:

1. **Prometheus 面试你**
   - 作为你的个人顾问，提出澄清问题
   - 同时研究你的代码库以理解你的需求
   
2. **生成工作计划**
   - 基于面试生成详细工作计划
   - 包含任务、验收标准和防护措施
   - 可选由 Momus（计划审查者）进行高精度验证
   
3. **运行 `/start-work`**
   - Orchestrator-Sisyphus 接管执行
   - 将任务分配给专业子智能体
   - 独立验证每个任务完成情况
   - 跨任务积累学习
   - 跨会话跟踪进度（随时恢复）

**正确的工作流程**:
```
1. 按 Tab → 进入 Prometheus 模式
2. 描述工作 → Prometheus 面试你
3. 确认计划 → 审查 .sisyphus/plans/*.md
4. 运行 /start-work → Orchestrator 执行
```

**⚠️ 重要**: 不要单独使用 `atlas` 而不使用 `/start-work`。Orchestrator 设计用于执行 Prometheus 创建的工作计划。

### 使用专业智能体

项目包含多个专业智能体，每个都有特定的用途：

| 智能体 | 默认模型 | 用途 |
|--------|---------|------|
| **Sisyphus** | Claude Opus 4.5 High | 主编排器，扩展思考能力 |
| **Oracle** | GPT-5.2 Medium | 只读咨询，高智商调试 |
| **Librarian** | GLM-4.7 Free | 多仓库分析、文档、GitHub 搜索 |

| **Multimodal Looker** | Gemini 3 Flash | PDF/图片分析 |
| **Prometheus** | Claude Opus 4.5 | 战略规划，面试模式 |

## 常见问题

### Q1: 我没有 Claude 订阅，还能使用吗？

**答**: 可以，但 Sisyphus 智能体可能无法达到最佳体验。你可以：
- 使用 GitHub Copilot 作为备用
- 使用 OpenCode Zen 模型
- 使用 Z.ai Coding Plan

但强烈建议使用 Claude Opus 4.5 以获得最佳体验。

### Q2: 如何切换智能体使用的模型？

**答**: 编辑配置文件 `~/.config/opencode/oh-my-opencode.json`:

```json
{
  "agents": {
    "sisyphus": {
      "model": "anthropic/claude-opus-4-5-high"
    },
    "oracle": {
      "model": "openai/gpt-5.2-medium"
    }
  }
}
```

### Q3: 如何禁用某个智能体或功能？

**答**: 在配置文件中禁用特定钩子：

```json
{
  "disabled_hooks": [
    "todo-enforcer",
    "comment-checker"
  ]
}
```

**⚠️ 警告**: 除非明确需要，否则不要更改默认配置。插件开箱即用，效果最佳。

### Q4: 支持多项目吗？

**答**: 是的！配置分为两级：
- **用户级**: `~/.config/opencode/oh-my-opencode.json` (全局设置)
- **项目级**: `.opencode/oh-my-opencode.json` (项目特定设置)

项目级配置会覆盖用户级配置。

### Q5: 如何查看智能体的工作进度？

**答**: 
- 在 Prometheus 模式下，查看 `.sisyphus/plans/` 目录
- 使用 `/status` 命令查看当前状态
- 后台任务会在终端显示通知

### Q6: 遇到问题如何调试？

**答**: 
1. 运行健康检查: `bunx oh-my-opencode doctor`
2. 检查日志: OpenCode 会在终端显示详细日志
3. 验证配置: 确保 JSON 语法正确（支持 JSONC 注释）
4. 查看 [GitHub Issues](https://github.com/code-yeongyu/oh-my-opencode/issues)

### Q7: 如何卸载？

**答**: 

```bash
# 1. 从配置中移除插件
jq '.plugin = [.plugin[] | select(. != "oh-my-opencode")]' \
    ~/.config/opencode/opencode.json > /tmp/oc.json && \
    mv /tmp/oc.json ~/.config/opencode/opencode.json

# 2. 删除配置文件（可选）
rm -f ~/.config/opencode/oh-my-opencode.json
rm -f .opencode/oh-my-opencode.json

# 3. 验证
opencode --version
```

## 最佳实践

### 1. 使用正确的模式

- **简单任务**: 使用 `ulw` 关键词
- **复杂任务**: 使用 Prometheus 模式 (Tab 键)
- **探索代码**: 让 Explore 智能体处理
- **架构决策**: 咨询 Oracle 智能体

### 2. 充分利用并行能力

Oh My OpenCode 可以同时运行多个智能体。在提示中包含 `ultrawork` 时，系统会自动：
- 并行探索代码库
- 并行查询文档
- 并行执行独立任务

### 3. 保持配置简洁

除非有特定需求，否则使用默认配置。插件经过精心调优，开箱即用。

### 4. 利用会话持久化

Prometheus 模式的工作计划会保存在 `.sisyphus/plans/` 目录。你可以：
- 随时中断工作
- 稍后使用 `/start-work` 恢复
- 在不同会话间保持进度

### 5. 监控成本

不同模型有不同的成本。根据任务复杂度选择合适的智能体：
- 简单探索: Explore (Grok Code - 快速便宜)
- 文档查询: Librarian (GLM-4.7 - 免费)
- 复杂任务: Sisyphus (Opus 4.5 - 最强但较贵)

## 性能优化建议

1. **上下文管理**: 让智能体处理上下文管理，不要担心 token 限制
2. **并行执行**: 使用 `ulw` 时系统会自动并行化任务
3. **增量工作**: 在 Prometheus 模式下，任务会被分解为可管理的小块
4. **缓存利用**: Explore 和 Librarian 会缓存查询结果
